Guideline: adding email notifications for a DocType
  1. Create (or reuse) an Email Notification Template in the Templates tab. Wording is fixed text, so write it for the one state it will be used for (e.g. "has been approved, now you can submit the P_11 form").
  2. Create an Email Manager record in Desk: Module = the DocType, Enabled, Default Template = your template.
  3. In its Doc Status table add one row per workflow state to notify on (e.g. Approved). A row can use its own template. Only list states the template wording fits.
  4. Config is cached for up to 5 minutes; clear cache and restart workers for changes to apply immediately.
  • When it sends: only when the workflow state changes into a listed state, on save/submit. One email per document per state (duplicates are blocked by Email Send Logs).
  • Recipient: the document owner (whoever created/applied) — exactly one user. Skipped if the owner is Administrator/Guest or disabled, so records created by system users send nothing.
  • Existing records: documents already in a state are not emailed retroactively.
  • Manual overrides: changing state from Kafka Control writes straight to the database and does not send an email.
  • Fund Sanction: the state is read from sanction_workflow_status (mirrors workflow_state); every other DocType uses workflow_state.
  • Check the Email Send Logs tab for Pending / Success / Failed and to resend.
